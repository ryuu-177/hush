# Hush

轻量的自托管聊天室：账号与邀请码、群聊、等级、语音通话 / 语音房、屏幕直播、文件仓、群聊音乐，并且可以像软件一样安装（PWA）。后端是 Node.js + Express + Socket.io，数据存在本地 SQLite 文件里，不依赖任何第三方云服务。

当前版本 **v0.11.1**。开源协议：[MIT](LICENSE)。

## 功能
- **账号与邀请制注册**：第一个注册的账号自动成为管理员；之后注册必须使用管理员生成的邀请码（随机、一次性、7 天有效）。登录失败过多会临时锁定。
- **群聊**：回复引用、2 分钟内撤回（管理员可撤回任何消息）、@提及、搜索聊天记录、翻看历史、断线自动重连并补齐消息。
- **个人资料与等级**：昵称、头像（图片裁剪 / 表情 / 文字）、主题色、个性签名、自定义背景横幅（裁剪）；登录和发言获得经验升级。
- **群聊音乐**：每人一个音乐仓库（按等级解锁 1~3 首，支持 flac / mp3 / wav / m4a / ogg / opus）；群聊歌单所有人同步收听（服务器统一进度，中途加入自动对齐，公平轮流排队，每人同时最多 2 首）；管理员可开关群聊音乐、是否允许成员切歌；每个人可单独静音 / 调音量，不影响语音。
- **语音**：一对一语音通话、多人语音房（最多 6 人）、说话音量提示（WebRTC 点对点）。
- **屏幕直播**：共享屏幕 / 窗口 / 标签页（可带电脑声音），其他人点头像观看。
- **文件仓**：拖拽 / 粘贴 / 选择上传，按类型筛选、搜索、排序；图片、PDF、音视频、文本在线预览（HTML / SVG 只显示源码，不会执行）。
- **PWA**：安装到桌面或手机主屏幕、独立窗口、新消息系统通知、未读角标、离线提示页、新版本自动提示；手机端完整适配。

## 环境要求
- **Node.js 22.13 或更高**（使用内置的 `node:sqlite`，无需编译任何原生模块）。
- 依赖只有 `express` 和 `socket.io`。

## 快速开始
**Windows**
1. 到 https://nodejs.org 下载安装 LTS 版本（22.13+）。
2. 下载本仓库（或 Release 里的压缩包）并解压，双击 `start.bat`。第一次会自动 `npm install`，需要联网。
3. 浏览器会打开 http://localhost:3000 ，注册第一个账号（自动成为管理员，不需要邀请码）。

**macOS / Linux**
```bash
git clone https://github.com/ryuu-177/hush.git
cd hush
npm install
npm start          # 默认监听 0.0.0.0:3000
```

### 可选环境变量
| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `MAX_FILE_MB` | `50` | 单个文件上传上限（MB） |
| `MAX_VIEWERS` | `5` | 每个屏幕直播的最大观看人数 |
| `MUSIC_MAX_MB` | `100` | 单首音乐上传上限（MB） |
| `ICE_SERVERS` | Cloudflare / 小米 / B 站 STUN | WebRTC 的 STUN / 静态 TURN 列表，JSON 数组 |

| `CF_TURN_KEY_ID` / `CF_TURN_API_TOKEN` | 无 | Cloudflare Realtime TURN 密钥（也可写在 `turn.json`） |

**Cloudflare TURN 中转（v0.11.1）**：直连打不通时（严格 NAT、国内跨运营商等）语音 / 直播自动走中转。在 `server.js` 同目录新建 `turn.json`（已在 `.gitignore` 里，切勿提交）：
```
{"keyId":"你的 TURN Key ID","apiToken":"你的 TURN API Token"}
```
服务器按需向 Cloudflare 申请短期凭证（24 小时，用过一半自动换新），只发给已登录用户；Cloudflare 不可用时自动退回只用 STUN。查本月中转流量：`node turn-usage.js`（需要账户 ID 和有 Account Analytics 读权限的 API 令牌，写在 `turn.json` 的 `accountId` / `analyticsToken` 或环境变量 `CF_ACCOUNT_ID` / `CF_ANALYTICS_TOKEN`）。

## 管理员与邀请码
- 全新安装时第一个注册的账号自动成为管理员。
- 设置其他管理员：在 Windows 上双击 `make-admin.bat` 输入用户名；或运行 `node make-admin.js 用户名`（取消：`node make-admin.js 用户名 off`）。
- 管理员在左侧栏“邀请新成员”里生成邀请码，发给要注册的人；也可以查看最近 50 个邀请码的状态，删除未使用 / 已过期的码。

## 数据与备份
- 账号、聊天记录保存在 `data.db`（SQLite），上传的文件在 `uploads/`（音乐在 `uploads/music/`，个人背景在 `uploads/bg/`）。备份时两者一起备份；删除它们等于重置全部数据。
- 这两项已在 `.gitignore` 中排除，不会被提交。
- 升级时直接覆盖程序文件即可，数据库会在启动时自动补上新字段。

## 让别人访问
### 同一局域网
其他设备打开 `http://你电脑的局域网IP:3000`（Windows 用 `ipconfig` 查看 IPv4 地址），防火墙提示时选择允许。
注意：浏览器只允许在 **https** 或 **http://localhost** 下使用麦克风、屏幕共享、PWA 安装和通知，局域网 http 地址只能聊天。

### 用 Cloudflare Tunnel 发布到公网（推荐）
不需要公网 IP，也不用开放路由器端口：
1. 在 Cloudflare 添加你的域名，并安装 [`cloudflared`](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)。
2. 登录并创建隧道：
   ```bash
   cloudflared tunnel login
   cloudflared tunnel create hush
   cloudflared tunnel route dns hush chat.你的域名
   ```
3. 运行隧道，把流量转到本机 Hush：
   ```bash
   cloudflared tunnel run --url http://localhost:3000 hush
   ```
4. 之后用 `https://chat.你的域名` 访问。Hush 和隧道两个程序都要保持运行（先后顺序无所谓）。

只想临时试一下，可以用 `cloudflared tunnel --url http://localhost:3000` 获得一个随机的 `trycloudflare.com` 临时网址（每次重启都会变）。
隧道凭证（`~/.cloudflared/` 下的 `cert.pem` 和 `*.json`）是私密文件，不要提交到仓库。

### 部署到服务器
在任何能运行 Node.js 22.13+ 的服务器上 `npm install && npm start`，再用 Nginx / Caddy 等反向代理配置 HTTPS（需要转发 WebSocket），或者同样在服务器上运行 Cloudflare Tunnel。

## 安装成软件（PWA）
必须用 **https 地址**打开才能安装。
- **电脑（Chrome / Edge）**：登录后点左下角 **⚙ 设置 → 安装 Hush**，或点地址栏右侧的安装图标。卸载：在 Hush 窗口右上角“⋯”→“卸载 Hush”。
- **安卓（Chrome / Edge / 三星浏览器）**：点左上角头像 → **设置 → 安装 Hush**，或浏览器菜单“安装应用 / 添加到主屏幕”。
- **iPhone / iPad（Safari）**：点底部 **分享** → **添加到主屏幕**。iOS 16.4+ 才支持通知，并且只能从主屏幕图标打开时开启。

**消息通知**：在“设置 → 消息通知”中开启。Hush 在后台时有新消息会弹系统通知，@你的消息一定提醒。本版本没有服务器推送，完全关闭 Hush 后收不到通知。
Hush 只缓存界面外壳、图标和离线页；消息、文件、头像接口永远不缓存。

## 等级规则
每天首次登录 +20 经验，发消息 +2（每 5 秒最多算一次）。升到第 N+1 级需要 20×N² 经验。规则在 `server.js` 顶部，可自行修改。

## 安全说明
- 密码加盐哈希存储；登录凭证只放在请求头里，不出现在任何链接中。
- 音乐播放使用有时效的 HMAC 签名链接（不包含登录凭证），支持 HTTP Range；上传的音乐和背景图都会检查文件头。
- 下载 / 预览文件必须登录；文件按随机编号存放，HTML / SVG 等只作为文本显示或下载，不会在浏览器中执行。
- 语音和直播通过 WebRTC 点对点传输，服务器只在同一通话 / 语音房内的已登录用户之间转发信令。
